Maina ships a skills package alongside the CLI: [Agent Skills](https://agentskills.io/specification) that teach AI coding agents the v1 flows. Run `bun run docs:manifest` for the current skill list.

## What Are Skills?

A skill is a folder holding a `SKILL.md`: YAML front matter with a `name` (the folder's name) and a `description` of what the skill does and when to use it, then Markdown instructions. Hosts that support Agent Skills (Claude Code, Codex, Cursor and others) read every skill's description at the start of a session and load a skill's full instructions only when the task matches it:

- **The description** (at most 1024 characters) is what the agent scans to decide whether a skill is relevant. There are no trigger lists: the description is the match.
- **The body** (under 5,000 tokens) is read only when the skill activates.

Skills are the **knowledge layer**. The CLI, the MCP server and the hooks are the **automation layer**: the skills tell the agent when to call them and what to do with the answers.

## Available Skills

| Skill | Purpose | When it activates |
|-------|---------|-------------------|
| `gate` | How maina's action gate allows, asks about or denies risky actions, and what to do (and never do) after an ask or a deny. | A tool call is stopped by the gate, or before a destructive or irreversible action |
| `verify` | Run the verification pipeline, fix findings on changed lines, commit through maina and produce receipts. | After editing code, before committing or saying the task is done |
| `spec` | Spec-first features: `spec.md` (what and why), `plan.md` (how) and `tasks.md`, checked with `spec_check`, then implemented test-first. | Starting a feature, or editing a feature's spec, plan or tasks |
| `triage` | Two-stage review of a diff, triaged into blocking, advisory and info, and deciding which findings are real. | Before opening or merging a pull request, or when handed review findings |
| `graph` | What a change can affect (callers, dependents, covering tests, blast score) and the minimal source to read, from the code graph. | Before changing code others depend on, or instead of reading whole files |

## Installation

Skills ship in two ways, and only these two:

**In the maina plugin.** The Claude Code, Cursor and Codex plugins, and the Agent Plugins package, bundle every skill under `skills/<name>/SKILL.md`, namespaced under the plugin where the host does that (for example `maina:verify` in Claude Code). The plugin's skills run the CLI through the launcher the plugin bundles, so nothing needs to be on `PATH`.

**In `.agents/skills`.** `maina setup` copies every skill into `<your-repo>/.agents/skills/<name>/SKILL.md`, the project location Agent Skills hosts discover skills in. Idempotent: re-running setup only rewrites maina's own skills that changed. A skill of the same name that maina did not write (its front matter lacks `metadata.author: mainahq`) is never overwritten; setup warns and leaves it.

The source lives in `packages/skills/` of the Maina repository and is published as `@mainahq/skills`:

```
packages/skills/
  gate/SKILL.md
  verify/SKILL.md
  spec/SKILL.md
  triage/SKILL.md
  graph/SKILL.md
```

## How Skills Work

Each skill follows the same structure:

1. **Front matter**: `name`, `description`, `license`, `compatibility` and `metadata`, the fields the Agent Skills spec defines, and nothing else.
2. **When to use**: the situations the skill is for, in more detail than the description.
3. **Steps**: what to do, in order, naming the MCP tool and the CLI command for each step.
4. **Example**: one worked case.
5. **Notes**: limits and related skills.

Every skill ends in verification: the agent confirms its work passes the project's checks before moving on. This is the core Maina principle: verify before merge.

## Skills vs CLI vs MCP

| Capability | CLI | MCP | Skills |
|-----------|-----|-----|--------|
| Runs tools directly | Yes | Yes | No (guides the agent) |
| Teaches when to use each tool | No | No | Yes |
| Cross-platform | Terminal only | MCP-compatible IDEs | Any host that reads Agent Skills |
| Uses the engines | Directly | Via the server | Via the CLI and MCP tools |
