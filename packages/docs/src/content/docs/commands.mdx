Maina commands are organized into seven workflow phases. Every command draws from the three engines -- Context, Prompt, and Verify -- as needed. Run `maina --help` to see the live top-level surface (internal commands like `analyze`, `stats`, and `sync` are hidden from top-level help but still callable by name).

Commands that support `--json` for machine-readable output (JSON envelope with `{ data, error, meta }`): `analyze`, `commit`, `context`, `doctor`, `review`, `slop`, `stats`, `verify`, `wiki status`.

## Setup Phase

| Command | Description |
|---------|------------|
| `maina setup` | Guided first-time setup — detects stack, derives constitution from your existing rule files, materialises skills, kicks off the wiki in background. `--yes` skips prompts; `--ci` emits one JSON object per phase; `--update` refreshes managed regions; `--reset` backs up `.maina/` and starts fresh; `--legacy-agents` also writes retired agent files (`.clinerules`, `.roo/`, `.aider.conf.yml`, …); `--plugin` is the non-interactive host-plugin mode that writes only `.maina/` and managed regions of existing files. Idempotent: never overwrites your files, and backs up originals to `.maina/backups/` before the first edit. |
| `maina doctor` | Health check across tools, engines, AI status, wiki coverage, and MCP integrations. Reads each host's MCP config where the host reads it (`.mcp.json` / `~/.claude.json`, `~/.cursor/mcp.json`, `~/.codex/config.toml`, …) and reports scope per client: `project`, `global`, `both`, or `missing`. Then launches every configured maina entry exactly as configured, under the host's minimal GUI environment (`PATH=/usr/bin:/bin:/usr/sbin:/sbin` on macOS, `HOME`, nothing else), and checks the MCP handshake and which maina version answered. User-scope entries (`~/.claude.json`, `~/.cursor/mcp.json`, …) always launch. A project-scope entry (`.mcp.json`, `.cursor/mcp.json`, …) comes from the repo, so doctor launches it only when it is one of maina's own launcher forms (the `maina` binary, `bunx`/`npx @mainahq/cli@<version>`, or a runtime plus the CLI's entry file, each with `--mcp` only, no `env`, and no file inside the repo); any other is not executed and is reported `skipped` with the fix `maina doctor --launch-project`. Once per repo it checks the root the server resolves, `.maina/policy.json` validity, and the local model (reported as not installed until the model backend ships). Every failed check prints a fix command; an entry left in a Claude Code `settings.json` (which Claude never reads) is reported as broken. Exits `1` when any check fails. |
| `maina doctor --fix` | Run the printed `maina mcp add --client X --scope Y` fix for every `missing` MCP row and every host entry that failed to launch. Other fixes (editing a policy file, pulling a model) are printed, not run. Confirms interactively; `--yes` skips (`--json` implies `--yes`). |
| `maina doctor --launch-project` | Also launch project-scope entries that are not maina's own launcher. **This runs code the repo controls**: use it only in repos you trust. |
| `maina doctor --json` | Emit `{tools, engines, aiStatus, wikiHealth, mcpHealth: { integrations: [{client, scope, fix?}] }, hostHealth: { ok, launchEnv, hosts: [{host, scope, path, command, status, checks: [{id, status, message, fix?}]}], runtime: [{id, status, message, fix?}] }, cacheStats}` for CI consumption. `status` is `pass`, `skipped`, `warn` or `fail`; a project entry doctor did not execute has a `launch` check with `status: "skipped"`, the reason in `message` and `fix: "maina doctor --launch-project"`. Exit code `1` when `hostHealth.ok` is false (a skipped check never fails it). |
| `maina mcp add` | Install the maina MCP server in every detected client's global config (Claude Code, Cline, Codex, Continue, Copilot, Cursor, Gemini CLI, OpenHands, Roo Code, Windsurf, Zed AI). Auto-detects; pass `--client <list>` to override or `--scope project` for per-repo install. |
| `maina mcp remove` | Strip the maina MCP entry from each client's config. Defaults to global scope; same `--client / --scope global\|project\|both / --dry-run / --json` flags as `add`. |
| `maina mcp list` | Show maina MCP install status per client. |

## Brainstorm Phase

Start here. Explore ideas before committing to implementation.

| Command | Description | Context Needs |
|---------|------------|---------------|
| `maina brainstorm` | Interactive idea exploration -- generates a structured GitHub issue with user stories, acceptance criteria, edge cases. The starting point for every feature. | None |

## Define Phase

Set up your project and define architecture.

| Command | Description | Context Needs |
|---------|------------|---------------|
| `maina init` | Deprecated alias of `maina setup` (same flags). Prints a deprecation notice. | None |
| `maina configure` | Interactive project settings -- update constitution, conventions, visual URLs, tool preferences. | None |
| `maina ticket` | Create a GitHub Issue with automatic module tagging. Use `--repo` for cross-repo issue creation with aliases from `.maina/config.json`. | Semantic (module structure) |
| `maina context` | Generate focused codebase context. Loads all 4 layers in exploration mode (80% budget). Writes to `.maina/CONTEXT.md` by default; use `--output <path>` to override. An existing `CONTEXT.md` at repo root is preserved unless `--force`. | All 4 layers (exploration) |
| `maina explain` | Visualize codebase structure with Mermaid dependency diagrams and module summaries. | Semantic (dependency graph) |
| `maina design` | Create an Architecture Decision Record (ADR) with HLD/LLD sections. Use `--hld` for AI generation. Use `--auto` for fully automated ADR creation from plan context. | Semantic (existing ADRs) |
| `maina review-design` | Review an ADR against existing decisions and the project constitution. Blocks empty ADRs. | Semantic (ADRs + constitution) |

## Build Phase

Plan, specify, and commit.

| Command | Description | Context Needs |
|---------|------------|---------------|
| `maina plan` | Create a feature branch with auto-numbered directory and structured spec/plan/tasks. Resets workflow context. | Working + Semantic |
| `maina spec` | Generate TDD test stubs from plan. Scores spec quality across clarity, testability, completeness. Use `--auto` for fully automated spec generation without prompts. | Working + Episodic |
| `maina commit` | Run syntax guard, parallel verification (19+ tools), then git commit. Records stats + workflow step. | Working only (fast) |

## Verify Phase

Prove correctness before merge.

| Command | Description | Context Needs |
|---------|------------|---------------|
| `maina verify` | Full verification pipeline (19+ tools). Diff-only by default. | Working + Semantic |
| `maina verify --deep` | Force the standard-tier AI semantic review (spec compliance, architecture); large or sensitive diffs get it without the flag. | Working + Semantic |
| `maina verify --tests` | Also run the tests the code graph says the change can break (the tests covering the change and its callers), plus changed test files. Bun projects only for now. | Working + Graph |
| `maina verify --cloud` | Submit diff to Maina Cloud for hosted verification. No local tool installs required. | Working |
| `maina verify --visual` | Add Playwright visual regression checks against baselines. | Working + Visual baselines |
| `maina slop` | Standalone AI slop pattern detection. `--all` for all tracked files. | Working |
| `maina review` | Comprehensive two-stage code review: spec compliance first, then code quality. | Working + Semantic |
| `maina analyze` | Check cross-artifact consistency: spec, plan, tasks, and code must align. | Semantic (all artifacts) |
| `maina pr` | Create a pull request with two-stage review + verification proof artifacts in the body. | All 4 layers |

## Cloud Integration

Authenticate, sync prompts, and manage teams.

| Command | Description |
|---------|------------|
| `maina login` | GitHub OAuth device flow. Stores token in `~/.maina/auth.json`. |
| `maina logout` | Clear stored credentials from `~/.maina/auth.json`. |
| `maina sync push` | Upload local prompts and constitution to the Maina cloud. |
| `maina sync pull` | Download team prompts and merge with local copies (conflict resolution included). |
| `maina team` | Show team info, members, and roles. |
| `maina team invite <email>` | Send an invite to join the team. |

## Wiki Phase

Compile and query codebase knowledge.

| Command | Description | Context Needs |
|---------|------------|---------------|
| `maina wiki init` | Compile codebase knowledge wiki from code, plans, specs, ADRs, workflows | Working, Semantic |
| `maina wiki init --background` | Fork the compile, seed `.maina/wiki/.progress.json`, return immediately. Poll with `maina wiki status`. `maina setup` uses this to keep onboarding under 60 s. | Working, Semantic |
| `maina wiki init --depth quick` | Compile only the top 20 PageRank-scored files. Used by `setup`'s background seed. | Working, Semantic |
| `maina wiki compile` | Incremental recompilation. `--full` for complete. `--ai` for LLM enhancement. `--dry-run` to preview. | Working |
| `maina wiki query <question>` | AI-powered search across wiki articles. `--save` to persist answer. | Wiki (L5) |
| `maina wiki status` | Health dashboard: articles by type, coverage, staleness, last compile. When a background compile is running, shows `Compiling… N%` + ETA; marked `stalled` when the progress file hasn't been updated in 10+ minutes. `--json` emits the structured snapshot. | None |
| `maina wiki lint` | Check wiki for stale articles, broken links, spec drift, decision violations | Working, Semantic |
| `maina wiki ingest <source>` | Add external docs to wiki/raw/ for compilation | None |

## Meta

Tune, learn, and diagnose.

| Command | Description |
|---------|------------|
| `maina learn` | Analyze feedback patterns across tasks and workflow steps. Propose prompt improvements via A/B testing. Use `--no-interactive` for CI. |
| `maina visual update` | Capture current screenshots as visual baselines for regression testing. |
| `maina prompt edit <task>` | Open a custom prompt template in `$EDITOR`. |
| `maina cache stats` | Show cache hit rate, total entries, tokens saved. |
| `maina stats` | Show commit verification metrics, trends, and quality evolution. |
| `maina digest` | This week's gate digest from `.maina/decisions.db` (blocked, asked, allowed, overrides, top blocked classes) plus a short card that is safe to share: numbers and Maina's action class names only, no code, paths or repo names. `--week yyyy-ww` picks another ISO week, `--card-labels` adds tool names and rules to the card, `--json` emits the `{ data, error, meta }` envelope. `--send` delivers the card to the channels in the `digest` section of `.maina/config.json` (an https `webhook.url`, or `email.to` through the local `sendmail`). Nothing is sent unless a channel is configured. |
| `maina benchmark` | Run verification benchmarks comparing tools. |
| `maina doctor` | Check tool installation status (19+ tools) and engine health. |
| `maina status` | Show current workflow state, active feature branch, and verification summary. |

## Verification Pipeline

Maina's verify pipeline runs 19+ tools in parallel:

| Tool | Type | Language |
|------|------|----------|
| Biome | Syntax guard | TypeScript/JavaScript |
| ruff | Linter | Python |
| go vet | Linter | Go |
| clippy | Linter | Rust |
| PHPStan/Psalm | Static analysis | PHP |
| TypeScript (`tsc`) | Type checking | TypeScript |
| Semgrep | SAST (2000+ rules) | All |
| Trivy | Dependency CVEs | All |
| Secretlint | Secret detection | All |
| SonarQube | Quality gates | All |
| Stryker | Mutation testing | TypeScript/JavaScript |
| diff-cover | Coverage on changed lines | All |
| Consistency check | Cross-artifact alignment | All |
| AI review | Semantic code review | All |
| Slop detector | AI-generated pattern detection | All |
| Playwright | Visual regression testing | Web |

Tools are auto-detected and auto-skipped if not installed. Run `maina doctor` to see status.

## Multi-Language Support

Maina detects your project language from marker files and adapts:

| Language | Marker Files | Syntax Tool |
|----------|-------------|-------------|
| TypeScript | `tsconfig.json`, `package.json` | Biome |
| Python | `pyproject.toml`, `setup.py`, `requirements.txt` | ruff |
| Go | `go.mod` | go vet |
| Rust | `Cargo.toml` | clippy |
| PHP | `composer.json` | PHPStan / Psalm |
| C# (.NET) | `.sln`, `.csproj`, `global.json` | dotnet format |
| Java/Kotlin | `pom.xml`, `build.gradle` | Checkstyle |

## Workflow Context

Every command records its outcome to `.maina/workflow/current.md`. This rolling summary is forwarded between steps so each phase has context from prior phases. Background RL feedback records every step for prompt evolution.

## Exit Codes

All commands return structured exit codes for CI integration:

| Code | Meaning | Description |
|------|---------|-------------|
| `0` | Passed | No error-severity findings |
| `1` | Findings | Error-severity findings found |
| `2` | Tool failure | A verification tool crashed |
| `3` | Config error | Missing config, bad arguments |

## Common Workflows

### First-time setup

```bash
maina setup             # Detect, tailor and scaffold (idempotent)
maina configure         # Set architecture constraints and conventions
maina doctor            # Verify tool health, list missing tools
```

### Daily development

```bash
maina plan my-feature   # Start feature with structured planning
maina spec              # Generate TDD test stubs
# ... write code ...
maina commit            # Verify (19+ tools) and commit
maina pr                # Create PR with verification proof
```

### Visual verification

```bash
maina configure         # Set visual URLs
maina visual update     # Capture baseline screenshots
# ... make changes ...
maina verify --visual   # Compare against baselines
```

### Prompt tuning

```bash
maina learn             # Analyze per-step feedback and evolve prompts
maina stats             # Track improvement over time
```
