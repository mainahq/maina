The runtime can now serve the local `system1` model. `maina model pull` downloads the pinned model release once, into the host plugin's data dir or `~/.maina/models`. It checks the hash and signature of every file before it moves the release into place, so a tampered download never reaches the cache. `maina model status` shows the pinned release, whether it verified and which engine runs it. `maina model verify` checks the cached release again. At each start, the resident runtime verifies the cached release again, loads it, and runs one parity fixture through its own path. If any step fails (a tampered file, an artifact it cannot read, an engine that will not load, a parity mismatch, an engine error at run time), `system1` turns itself off for the rest of the session. The runtime then shows the reason once, for example `system1: model 0.3.0 failed verification (model int8: sha256 mismatch); using rules and heuristics`, and the rules and heuristics decide as before. The model also runs in shadow beside the incumbent backend for every type it covers. The runtime never downloads a model on its own. No release is pinned yet, so behaviour does not change until one ships. `@mainahq/core` now exports `SYSTEM1_TYPES` and the `BackendCalibration` type, and the precomputed backend keeps a model's calibration on every decision it answers.
