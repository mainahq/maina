MCP server v2 tool set (FR-MCP-1, FR-MCP-2, FR-MCP-4). The server now registers at most eight tools by default: `verify`, `decide`, `impact`, `context`, `review_triage`, `spec_check`, `receipt` and `status`. Every tool takes an optional absolute `root` plus explicit `files`, `paths` or a `query` (relative paths resolve against the root, never the process working directory; paths outside the root are refused) and answers with a text summary plus structured content in a `{ data, error, meta }` envelope described by an output schema. `verify` now reports each tool's status (`passed`, `failed`, `skipped`) and why a tool was skipped, so MCP clients see skipped-tool notices like `maina verify --json` does (#421). The tool set is chosen with `--tools` or `MAINA_MCP_TOOLS` (comma-separated, `default` for the default set) and applied through the SDK's public `registerTool` only. The DeepWiki-compatible tools (`ask_question`, `read_wiki_structure`, `read_wiki_contents`) are reachable only through that allow-list, and `read_wiki_contents` refuses a page outside the wiki. Removed: the `list_tools` meta-tool, `--all-tools`, `MAINA_MCP_STRICT_TEN`, the private-registry pruning, and the 1.x tools `getContext`, `getConventions`, `reviewCode`, `checkSlop`, `explainModule`, `suggestTests`, `analyzeFeature`, `wikiQuery` and `wikiStatus`. The package API is now `createMcpServer(runtime, { tools })`, `startMcp(runtime, { tools })`, `startServer({ argv, env, cwd })` and `systemRuntime(...)`. `@mainahq/core` exports `hasFullCodeGraphIndex` and `systemFs`.
