Decisions can now carry diagnostics from a model backend. A `BackendAnswer` may include `diagnostics: { calibrated, escalate, truncated, windows, actionClassProbs }`, and `decide` validates it and copies it onto the `Decision`. The contract is numbers only: `calibrated` is the pre-threshold distribution with one probability per option, in option order; `escalate` is the probability that the answer is wrong; `truncated` is a boolean; `windows` is a positive integer; and `actionClassProbs` maps action class ids to probabilities. `decide` drops any other field, and a malformed one is an `invalid_answer`. The decision log stores each field in a new nullable column (`calibrated`, `escalate`, `truncated`, `windows`, `action_class_probs`). `migrateDecisionLog` adds these columns to an existing log without rewriting a row, so the log stays append-only, and rows written before the columns existed read back without diagnostics. When `escalate` reaches the type's cutoff, FP / (FP + FN) from its `error_costs`, `decide` escalates the decision: an `action.risk` answer becomes `ask` and keeps the model's distribution as `diagnostics.calibrated`, and any other type's answer stands but is marked `escalated`. `confidenceThreshold(policy, type, backend, escalated)` is then infinite, so triage, the spec analyzer, tier routing and `maina decide` do not act on it. Promotion and the drift guard now score a record at the calibrated probability of its answer when the log has one, so a thresholded `ask` logged at p = 1 no longer counts as certain. `system1Version` builds a System 1 backend version as `<manifest version>+<model sha12>+<calibration sha12>/<engine>`, which keeps model builds, calibrations and engines apart in `modelHash`.
